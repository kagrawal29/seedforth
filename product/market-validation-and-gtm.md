## Decision this program must make

Determine whether Mycelium should become a market product, for whom, around which urgent job, with which ownership contract and GTM motion.

The program must be capable of narrowing, changing, or stopping the proposed build. Research volume is not success; reduced uncertainty and paid behaviour are.

## Current thesis

People operating several autonomous agents are becoming managers of digital work. Their bottleneck shifts from generation to context, attention, authority, intervention, evidence, and continuity across agents, devices, teammates, and model providers.

Proposed job:

> While several AI agents are working, help me understand what matters, intervene from anywhere, and continue through whichever AI I prefer without rebuilding context.

Proposed initial segment:

- technical founders;
- AI-native product leaders;
- agencies and consultancies;
- small engineering teams already using multiple coding/research agents.

Proposed wedge:

> Remote supervision and continuity for long-running coding-agent work.

Proposed category:

> User-owned operational memory and control layer for human-agent teams.

All of the above remain hypotheses.

## Evidence already observed

- users operate multiple concurrent coding-agent sessions and lose target/session clarity;
- users build Tailscale, SSH, tmux, Discord, and custom mobile workarounds;
- users manually copy context between AI providers;
- Omnara demonstrates direct competition and a willingness to try/pay modestly for remote agent supervision;
- capital is flowing into coding agents, agent engineering, orchestration, memory, and enterprise governance;
- enterprise “agent control plane” is crowded;
- trust and human intervention remain adoption constraints.

The evidence map slice must preserve citations and confidence rather than treating this summary as final truth.

## Product principles to test

1. Attach to existing work; do not require migration before value.
2. Read-only discovery precedes authority.
3. User confirms the proposed project/work map.
4. The user owns, exports, corrects, deletes, and can self-host context.
5. External AI applications receive capabilities, never raw infrastructure credentials.
6. Conversation remains free; durable effects are structured, scoped, and verified.
7. Optimize cost per verified outcome, not token volume or agent activity.
8. Open-source the minimum complete ownership path.
9. Monetize hosted reliability, synchronization, collaboration, governance, and support.
10. Do not claim cross-AI portability, cost savings, or trust without behavioural proof.

## Stage gates

### Problem
20 qualified interviews; 60% recent problem incidence; 40% multi-tool same-project usage; corroborating behavioural evidence.

### Behaviour
Five connected live-work design partners; repeated weekly use; measurable reduction in recovery or coordination time.

### Payment
Three paid pilots attributable to the target job.

### Economics
Controlled improvement in cost per verified outcome after including all model, infrastructure, human, failure, and quality costs.

## GTM working model

Start founder-led with high-intent technical users publicly displaying the workaround:

- multiple sessions;
- remote/mobile control requests;
- agent-session dashboards;
- context migration problems;
- homegrown Discord/tmux/Tailscale systems.

Use open source as proof of ownership and an agent-facing distribution surface. The first activation must take minutes:

1. run Mycelium locally or create a hosted workspace;
2. connect GitHub and one agent runtime read-only;
3. review the reconstructed work map;
4. connect any MCP-capable AI;
5. call `orient`;
6. inspect or ask one live stream;
7. enable one bounded control.

The hosted offer wins on dependable remote access, backups, mobile intervention, synchronization, notifications, and team collaboration—not data captivity.
